# Manoel Amaro's personal site

A Jekyll site published at <https://manoamaro.github.io/>. The frontend uses HTML and CSS; JavaScript is not required.

## Local development

Use the latest Ruby 3.4 patch release and Bundler 2.6 or later. `.ruby-version` selects the Ruby 3.4 series for CI and compatible version managers. With rbenv, install a specific 3.4 patch version and use `rbenv shell <version>` to select it (rbenv requires an exact installed version).

```sh
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve --livereload
```

Open <http://127.0.0.1:4000/>. To include unpublished drafts, add `--drafts` locally. Drafts are excluded from production builds.

## Validation

```sh
JEKYLL_ENV=production bundle exec jekyll build --strict_front_matter --trace
bundle exec ruby scripts/check_site.rb
```

The checker validates generated HTML, internal links and fragments, image descriptions, canonical URLs, feed and sitemap XML, and the absence of source/build files in the public output. It intentionally does not fail builds on temporary external website outages.

## Publishing

`.github/workflows/pages.yml` builds and checks pull requests. Pushes to `master` and manual runs from `master` also upload and deploy the generated `_site` artifact using the `github-pages` environment.

The repository's **Settings → Pages → Build and deployment → Source** must be **GitHub Actions**. HTTPS should remain enforced. No personal access token is needed by the workflow. The build uses Jekyll 4 directly rather than the older `github-pages` gem or bundled Jekyll action.

Keep `_config.yml`'s `url` aligned with the actual Pages URL. `baseurl` is empty for this user site. If adding a custom domain, configure its DNS and Pages settings first, then update `url` and verify HTTPS. Preserve existing published post URLs.

## Content and maintenance

- `index.html`: introduction and homepage sections.
- `_data/profile.yml`, `_data/jobs.yml`, `_data/education.yml`, `_data/projects.yml`: profile, skills, languages, experience, education, and public projects. Updated from the current `~/Developer/curriculum/cv.tex` on 2026-10-31; keep these entries aligned when the CV changes.
- `_posts/`: published Markdown posts. Use `YYYY-MM-DD-slug.md`; the post layout is applied automatically.
- `_drafts/`: unpublished work; never deployed by the production workflow.
- `_includes/profiles.html` and `_config.yml`: profile links and metadata.
- `stylesheets/styles.css`: navy and mint design, responsive layout, print styles, and syntax highlighting.
- `assets/fonts/`: self-hosted Inter variable font and its SIL Open Font License.
- `assets/icons/`: Bootstrap Icons arrow and its MIT license.

Analytics, advertising, and Disqus embeds have been removed. The Google verification file and historical post content are preserved. RSS at `/feed.xml`, sitemap, canonical URLs, and social metadata are generated by Jekyll plugins.

The homepage uses a text-led introduction, writing and background overview, numbered projects, and experience and education lists. Personal photographs are excluded from the published output and social metadata; the original files remain in the repository. The notes index remains at `/posts.html`, and historical article URLs are unchanged. The site uses no JavaScript or external font requests. The earlier layout was based on the orderedlist theme.

Dependabot checks Ruby gems and Actions monthly. Review its pull requests and the build result before merging. To refresh dependencies manually, run `bundle update`, rebuild, and run the checker; commit `Gemfile.lock`. The Linux platform in the lockfile supports CI alongside local macOS development.
